# Framework for comparing the current project with the ideal

This is the evaluation rubric for the next phase. It does not yet claim how well the current
repository satisfies the ideal.

## Evaluation scale

| Score | Meaning |
| ---: | --- |
| 0 | absent |
| 1 | named or mocked only |
| 2 | partial contract or isolated prototype |
| 3 | coherent implemented slice with tests |
| 4 | integrated, traceable and useful in a real workflow |
| 5 | production-capable, evaluated and reusable across brands |

Every score must cite repository evidence and distinguish schema, fixture, projection, prototype
and observed runtime behavior.

## A. Product thesis

- Does the project model organizational meaning rather than merely brand assets?
- Is brand defined as the manifestation of company reality, philosophy and choices?
- Does the architecture support applications beyond content generation?
- Is the difference between universal platform and brand-specific world explicit?
- Is human sovereignty over identity encoded operationally?

## B. Brand World completeness

- Is there a coherent universal skeleton?
- Are entity, event, state, relation, claim, evidence and context distinct?
- Can brand-specific extensions be added without changing core agent code?
- Can absent, unknown, not-applicable and not-connected states be distinguished?
- Can overlapping and nested containers be represented?
- Are cross-system relations first-class and semantically typed?

## C. Evidence and epistemics

- Does every material record retain source and derivation?
- Are observation, interpretation, hypothesis, proposal, approval, rejection and supersession
  distinct?
- Are authority, scope, confidence/uncertainty, valid time and recorded time represented?
- Are contradictions and competing interpretations preserved?
- Is approved brand intent distinct from externally verifiable factual truth?
- Can a user trace any high-level statement to bounded evidence and original source?

## D. Temporal world and versioning

- Are revisions append-oriented rather than overwritten?
- Can the system answer what was true, according to whom, at a past time?
- Are branches, proposals, accepted changes and historical states distinct?
- Can upstream changes identify downstream stale or conflicting dependencies?
- Can different entity types evolve at different rates?
- Are manifestation policies and canonical representations versioned?

## E. Progressive abstraction and dimensional indexing

- Are raw source, evidence, observations, patterns, insights and strategic knowledge connected?
- Does abstraction preserve derivation rather than repeatedly summarize summaries?
- Can one object be retrieved across multiple semantic dimensions?
- Can retrieval filter by time, status, authority, scope, task and abstraction?
- Can an agent start with a high-level map and deepen only when needed?

## F. Context Compiler and routes

- Does context compilation accept agent, task, state and authority?
- Does it choose both relevant knowledge and the appropriate abstraction level?
- Does it combine semantic and analytical evidence?
- Does it expose omissions, conflicts and sufficiency judgments?
- Is the exact context seen by an agent recorded?
- Are routes and route policies inspectable, versioned and evaluated?

## G. Specialist intelligence

- Do specialists have distinct reasoning procedures rather than prompts alone?
- Are hypotheses, alternatives, disconfirming evidence and stopping rules explicit?
- Can a specialist ask, hold, branch or escalate?
- Does Brand Guardian inspect claims, identity, evidence and permissions?
- Can the Director coordinate without recomputing specialist work?
- Are reasoning versions evaluated against domain-specific cases?

## H. Work and agent organization

- Are Task, Artifact/Result, Event, Dependency and Status durable types?
- Do domain objects such as Insight, Recommendation, Decision and Experiment extend the Work Model?
- Do agents communicate by references to shared knowledge rather than prose duplication?
- Can work run in parallel while preserving dependency and review order?
- Are approvals, cancellation, retry, partial completion and idempotency coherent?
- Are runtime providers isolated behind stable adapters?

## I. Learning

- Are reaction, comment, correction, approval and outcome semantically distinct?
- Can weak signals improve retrieval without modifying canonical truth?
- Are performance results treated as evidence rather than automatic causality?
- Does every decision retain the context, reasoning, action and outcome needed for evaluation?
- Can the system identify where its retrieval, reasoning or simulation is unreliable?

## J. Simulation

- Are synthetic audience models anchored in real evidence?
- Are synthetic response, prediction and actual outcome kept separate?
- Does simulation surface segment differences, assumptions, trade-offs and failure modes?
- Does every simulation terminate in a proposed real test or a justified hold?
- Can systematic simulation bias be measured and calibrated over time?

## K. Artifact and manifestation intelligence

- Can artifacts be decomposed into elements and composition relations?
- Does each element receive task-specific context rather than one global prompt dump?
- Are global, local, relational, medium and situational factors represented?
- Are element quality and whole-composition quality evaluated separately?
- Can abstract principles produce channel-specific manifestation instructions?
- Are inheritance strength, overrides and conflicts explicit?
- Can shared recurring entities own canonical cross-product representations?
- Can artifacts become stale when their determining context changes?

## L. Human experience

- Is the primary experience organized around important decisions rather than dashboards?
- Are feed posts typed domain objects rather than raw logs?
- Does interaction provide clear semantic actions: like, correct, discuss, adjust, approve, reject?
- Can users progressively disclose reasoning, relations, history and evidence?
- Do agent avatars reflect actual state and remain accessible without motion?
- Is the interface visually quiet while agents carry identity, color and activity?
- Are consequential approvals complete enough for informed human judgment?

## M. Forward-deployed service readiness

- Can a new brand be onboarded through a repeatable discovery and validation process?
- Is client-specific content/configuration isolated from the universal platform?
- Can ontology extensions be proposed, reviewed, migrated and reused?
- Are source connection, extraction, contradiction review and approval supported?
- Does each deployment contribute evaluation cases and reusable learning?
- Can client #10 require materially less platform work than client #1?

## N. Commercial readiness

- Is one first ICP and high-value decision loop explicit?
- Is the deliverable understandable without ontology or agent-framework language?
- Does the system reduce client work compared with an agency engagement?
- Can recommendations be connected to measurable or inspectable consequences?
- Are setup, recurring maintenance and responsibility boundaries clear?
- Is there a credible path from managed service to repeatable platform economics?

## O. Security and governance

- Are tenants, datasets, users, agents, tools and resources isolated?
- Does every external action carry explicit authority and audit information?
- Are privacy, retention, deletion and provider rules represented?
- Are credentials and customer data bounded to the correct client?
- Can dangerous actions pause, request approval and resume safely?
- Are historical states recoverable without destructive mutation?

## P. Infrastructure discipline

- Are knowledge, analytical, work and runtime state stores semantically separated?
- Do adapters prevent Cognee, LangGraph, Harness or another provider from leaking into core types?
- Is there exactly one owner for agent lifecycle, tool execution, approvals and canonical knowledge?
- Are optional systems introduced only after a measured limitation?
- Are runtime claims supported by tests rather than configuration presence?

## Comparison outputs to produce

The eventual audit should emit:

1. a scored matrix with file/runtime evidence;
2. an ideal-to-current capability map;
3. existing strengths worth preserving;
4. semantic conflations and structural gaps;
5. modules that are overbuilt relative to the ideal;
6. missing end-to-end loops;
7. dependency and migration constraints;
8. a proposed target architecture;
9. a staged migration plan that preserves working behavior;
10. evaluation fixtures proving each promoted capability.

The comparison should not reward file count or vocabulary coverage. The governing question is:

> Can the system use a deeply modeled, approved and evidence-aware brand world to make an
> outstanding decision or artifact—and show exactly why it did so?
